Workflow Stories Factions Characters Units Dialogues Quests Scenes Tilesets
How this works: Each section below contains the JSON schema and a ready-to-use LLM prompt. Click Copy Prompt, paste it into any AI assistant (Claude, GPT, etc.), describe what you want, then paste the returned JSON array into the matching { } JSON import field in the Builder sidebar. Items with a matching _id update in place — everything else is appended.
🗺 Recommended Build Order

Build in this order so IDs are available when you need to cross-reference them. After each step, copy the _id values and paste them into the next prompt.

Factions — foundation; everything else references faction _ids
Characters — NPCs, heroes, quest givers; reference faction _ids
Units — enemy/army templates; reference faction _ids
Dialogues — conversations; note the id keys (not _id) for use in Scenes
Quests — missions; reference character _ids as giver_id; note quest _ids for Scenes
Scenes — cutscenes & triggers; wire in dialogue ids and quest _ids
Tilesets — independent; or use 🎨 Pixel Painter and import from the Tiles tab directly

💬 Dialogues dialogues.example.json ↗
FieldTypeNotes
_idstringAuto-generated if omitted
idstringREQUIRED — snake_case key used by Scenes e.g. "intro_01"
speakerstringName shown in dialogue box
portraitstringSprite key — leave empty
linesstring[]Each element = one text bubble
choicesobject[]Optional: [{"text":"…","next":"dialog_id or null"}]
LLM Prompt
Generate a JSON array of RealmKit Dialogue entries. Each entry must follow this exact schema:
{
  "_id": "dialog_<unique_short_id>",
  "id": "short_snake_case_key",
  "speaker": "display name",
  "portrait": "",
  "lines": ["line one text", "line two text"],
  "choices": [
    { "text": "player choice text", "next": "dialog_id_or_null" }
  ]
}

Rules:
- "id" must be a short snake_case key like "intro_gate_01" — Scenes reference this value
- "lines" is an array; each element is one separate text bubble
- "choices" is optional; use [] for linear dialogue (no branching)
- "next" in choices references another dialogue "id" or null to end
- Leave portrait as an empty string

Describe the conversations — who speaks, what they say, any branching choices, tone, context, etc.

Return only the raw JSON array, no explanation.

🎬 Scenes scenes.example.json ↗
FieldTypeNotes
_idstringAuto-generated if omitted
idstringREQUIRED — snake_case key for this scene
namestringHuman-readable label
triggerobjectWhen the scene fires (see table below)
stepsobject[]Ordered list of scene actions (see table below)

Trigger types

typeFires when…Extra field
onceGame loads for the first time"condition": "game_start"
enterPlayer enters a named zone"zone": "zone_id"
flagA game flag matches a condition"condition": "flagKey == value"
interactPlayer interacts with an entity"target": "entity_id"

Step types

typeEffectFields
dialogShow dialogue"id": "dialog_key"
blackout / fadein / fadeoutScreen transitionoptional "duration" ms
textFull-screen caption"text", "duration"
waitPause"ms"
soundPlay sound"id", optional "loop"
flagSet a game flag"key", "value"
spawnSpawn a unit"unit" (char _id), "x", "y"
combatTrigger a fight"enemy" (char _id), "flee_allowed"
rewardGive items/gold/xp"gold", "xp", "items"
quest_updateAdvance quest objective"quest_id", "objective" (0-based)
LLM Prompt
Generate a JSON array of RealmKit Scene entries. Each entry must follow this exact schema:
{
  "_id": "scene_<unique_short_id>",
  "id": "short_snake_case_key",
  "name": "human readable name",
  "trigger": {
    "type": "once | enter | flag | interact",
    "condition": "game_start  ← use this for 'once' type",
    "zone":      "zone_id     ← use this for 'enter' type",
    "target":    "entity_id   ← use this for 'interact' type"
  },
  "steps": [
    { "type": "fadeout",      "duration": 800 },
    { "type": "dialog",       "id": "dialog_id_key" },
    { "type": "fadein",       "duration": 600 },
    { "type": "flag",         "key": "flag_name", "value": "true" },
    { "type": "quest_update", "quest_id": "quests_xxx", "objective": 0 }
  ]
}

Step types available: dialog, blackout, fadein, fadeout, text, wait, sound, flag, spawn, combat, reward, quest_update
For dialog steps, use the dialogue "id" key (not _id).
For quest_update, use the quest "_id" value.

Dialogue ids available: [paste your dialogue id keys here]
Quest _ids available:  [paste your quest _id values here]

Describe the scenes — cutscenes, zone entry events, NPC interactions, combat triggers, number of entries, etc.

Return only the raw JSON array, no explanation.
🗺 Tilesets tilesets.example.json ↗
FieldTypeNotes
_idstringAuto-generated if omitted
namestringREQUIRED
pathstringRelative path to PNG e.g. "assets/tilesets/overworld.png"
tileWidthnumberWidth of one tile in pixels (default 32)
tileHeightnumberHeight of one tile in pixels (default 32)
colsnumberNumber of tile columns across the spritesheet

💡 Tip: Create tileset images in 🎨 Pixel Painter. Assets saved to the server appear automatically in the Builder's Tiles tab under "Import from Pixel Painter."

LLM Prompt
Generate a JSON array of RealmKit Tileset entries. Each entry must follow this exact schema:
{
  "_id": "tiles_<unique_short_id>",
  "name": "display name",
  "path": "assets/tilesets/filename.png",
  "tileWidth": 32,
  "tileHeight": 32,
  "cols": 8
}

tileWidth / tileHeight = size of one tile in pixels (typically 16, 32, or 64).
cols = number of tile columns across the spritesheet width.

Describe the tilesets needed — biomes, art styles, tile sizes, etc.

Return only the raw JSON array, no explanation.
